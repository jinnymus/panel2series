# Диагностика Panel2Series

Команды выполняются из корня репозитория. Сохраните UID дашборда, числовой ID панели, окно в Unix-миллисекундах, переменные и версию Grafana. Для задания HTTP также запишите ID из ответа 202. По этим данным можно повторить запрос и проверить результат.

## В отчёте нет ожидаемого ряда

Откройте панель в Grafana под тем же Viewer, выставите тот же абсолютный интервал и значения переменных. В Inspector → Data проверьте имена полей, метки и фактический шаг. Для многорядного JSON проверьте каждый refId отдельно. Следующая команда читает комплектный пример. Для диагностики замените путь на свой экспорт.

```sh
python3 - example/stores/prometheus-multi.json <<'PY'
import json, sys
with open(sys.argv[1]) as source:
    data = json.load(source)
print("window_ms", data["window_ms"])
if data["schema_version"] == 1:
    print(data["refId"], data["labels"], len(data["points"]), "points")
else:
    print("variables", data["variables"])
    for ref, result in data["results"].items():
        print(ref, result["status"], result.get("reason", ""))
        for i, series in enumerate(result.get("series", [])):
            print(" ", i, series["field"], series["labels"], len(series["points"]), "points")
PY
```

В комплектном примере A и C дают по три точки, B сообщает об ошибке. Для построения графика C из такого файла выполните:

```sh
python3 panel2series.py chart example/stores/prometheus-multi.json --ref C --series 0 --out /tmp/panel2series-c.svg
```

| Наблюдение | Что проверить и сделать |
|---|---|
| `empty` или ряд без точек в окне | Сверьте UTC-время, метки и выбранную переменную. В частности, проверьте сохранённое значение переменной в JSON. Передайте нужную скалярную переменную через `--var queue=demo` или поле `variables` HTTP-запроса. |
| `hidden` | Запрос скрыт в сохранённой панели. Выберите активный refId или согласуйте изменение панели с владельцем. |
| `error` только у части запросов | Прочитайте `reason`, воспроизведите целевой запрос в Grafana и проверьте права на источник. Укажите успешный refId для графика. Проверьте, что обе выбранные метрики доступны в обоих прогонах перед сравнением. |
| `Expected a query panel without transformations` | Проверьте ID панели и наличие targets. Для данных после преобразований используйте браузерный экспорт CSV. |
| `Selector ... matched ... series` | Выберите существующий refId и скопируйте точные `field` и `labels` из выгрузки. Для формата v1 поле `field` в селекторе опустите. |
| `outside the configured sampling grid` | Сопоставьте отметки времени с началом `window_ms` и шагом `step_ms`. Задайте окно и шаг, соответствующие исходному ряду. Анализ отвергает смещённые точки и дубликаты. |
| Лаг `insufficient` или `ambiguous` | Смотрите `lag.scores` в analysis.json. Проверьте число пар, постоянные значения, пропуски и повторяющиеся пики. Для малой выборки увеличьте окно с данными. Интерпретация и пример с задержкой 4 с приведены в [руководстве по анализу](ANALYSIS.md). |

## Отказ во входе или экспорте браузером

| Наблюдение | Следующий шаг |
|---|---|
| HTTP 401, `session expired or invalid` | Для пользовательской сессии повторите интерактивный вход и MFA. Для фонового процесса проверьте срок Viewer-токена, обновите секрет и перезапустите сервис с новым окружением. |
| HTTP 403 при чтении панели или запросе | Проверьте доступ Viewer к организации, папке и источнику данных. Зафиксируйте, что именно вернуло отказ. Успешный вход подтверждает лишь аутентификацию. |
| `Session belongs to a different Grafana URL` или ошибка прав файла | Передайте тот же базовый URL, что при входе, и путь к его сессии. Файл должен быть доступен только владельцу (`chmod 600`). |
| Нет модуля playwright/yaml или браузера Chromium | Активируйте окружение, в котором установлены библиотеки из browser-requirements.txt. Для Chromium из Playwright установите браузер тем же интерпретатором. Параметр `--channel chrome` выбирает локально установленный Chrome. |
| Тайм-аут CSV или меню | Откройте тот же Inspector вручную. Сверьте название элемента, версию Grafana и ключ в locators.yaml. Передайте файл переопределений через `--locators site.yaml`. Для 13.3.0 также проверьте заголовок панели и пункты Inspect → Data. [Пример YAML и порядок проверки](BROWSER.md). |
| CSV отличается от графика | Сверьте выбранный Inspector frame, переключатель преобразований, окно и переменные. PNG и CSV читаются отдельными запросами. Для воспроизведения используйте завершённый интервал со стабильными данными. |

Проверить доступность команд в активном браузерном окружении можно так:

```sh
python locator_doctor.py --version 13.3.0 --channel chrome
python browser_export.py --help
python sso_login.py --help
```

Профиль входа, поддерживаемые настройки и команды повторного использования файла сессии приведены в [AUTH.md](AUTH.md).

## HTTP-задание или авторепорт не завершается

Прочитайте статус на том экземпляре API, который выдал ID. Подставьте свой ID в переменную `JOB_ID`.

```sh
curl -sS -i "http://127.0.0.1:8765/jobs/$JOB_ID"
```

| Наблюдение | Следующий шаг |
|---|---|
| Ошибка подключения | Проверьте процесс job_api.py, адрес и порт. По умолчанию он слушает loopback. В контейнере loopback указывает на его собственное сетевое пространство. |
| HTTP 400 или 415 при POST | Прочитайте JSON-поле `error`. Проверьте заголовок Content-Type, ключи объекта, целые значения panel/start/end, условие start < end и лимиты анализа. |
| HTTP 404 | Для `Unknown job` проверьте ID и хранилище экземпляра. Для `Unknown artifact` проверьте статус и имя файла из `artifacts`. У готового экспорта это series.json, у анализа — analysis.json и SVG. |
| HTTP 409 при постановке анализа | Укажите два ID числовых экспортов со статусом succeeded, базовый прогон первым. |
| HTTP 429 | Очередь заполнена. Дождитесь завершения текущих заданий и повторите отклонённый запрос с паузой. |
| `failed` | Прочитайте `error`. Если задание прервалось при перезапуске, отправьте новый POST. При `Job exceeded 180 seconds` проверьте длительность запроса в Grafana или сузьте окно и диапазон лагов для анализа. |
| Авторепорт завершился по тайм-ауту | Проверьте URL задания из сообщения. Сервер продолжает обработку до своего лимита. При повторном запуске autoreport создаст новые задания. |
| `Choose a new report directory` | Используйте новый каталог для запуска авторепорта. Если артефакты уже собраны, пересоберите HTML командой `python3 example/reporting/report_builder.py КАТАЛОГ`. |

При запуске API ошибка блокировки каталога может означать, что этот `--store` уже использует другой процесс. Проверьте процессы и пути. Для диагностики после перезапуска используйте прежний каталог заданий. Политика хранения, структура запросов и воспроизведение Viewer-теста описаны в [HTTP_API.md](HTTP_API.md). Сведения о проверенных версиях и пределах совместимости приведены в [COMPATIBILITY.md](COMPATIBILITY.md).
