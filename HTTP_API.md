# HTTP API заданий и отчёты

Сервис принимает задания для одной настроенной Grafana. Клиенту отчётности нужны адрес API и параметры прогона. Viewer-токен хранится у сервиса. Для запуска достаточно Python 3 и стандартной библиотеки.

## Запуск

Задайте GRAFANA_TOKEN через секрет окружения процесса, выданный сервисной учётной записи Viewer с доступом к нужным панелям и источникам. Для частного центра сертификации укажите SSL_CERT_FILE с доверенным CA.

```sh
python3 job_api.py --grafana-url https://grafana.example.org --store ./job-data --port 8765
```

Запускайте экземпляр для доверенных потребителей. Каждый клиент, имеющий доступ к API, может запрашивать доступные сервисному Viewer данные. Для доступа с других машин настройте аутентификацию и TLS на обратном прокси. Адрес Grafana выбирает оператор при запуске процесса.

## Контракт

| Метод и путь | Назначение |
|---|---|
| POST /jobs/export | Поставить числовой экспорт панели в очередь |
| POST /jobs/analysis | Сравнить результаты двух завершённых экспортов |
| GET /jobs/{id} | Прочитать статус и имена готовых файлов |
| GET /jobs/{id}/artifacts/{name} | Скачать один готовый файл |

Отправляйте JSON с Content-Type application/json. При постановке API возвращает HTTP 202 и id. Сохраните id и опрашивайте статус с паузой. При succeeded можно скачивать перечисленные artifacts. При failed кадры и графики этого задания недоступны.

Пример запроса для панели учебного стенда:

```sh
curl -sS -H 'Content-Type: application/json' http://127.0.0.1:8765/jobs/export \
  -d '{"uid":"stores","panel":11,"start":1704067200000,"end":1704067320000,"variables":{"queue":"demo"}}'
```

start и end — Unix-время в миллисекундах. Повторите запрос для окна второго прогона. Готовый series.json содержит статусы отдельных запросов панели. При частичном отказе источника проверьте статусы нужных refId.

Для анализа передайте объект с exports (массив из двух id экспортов, базовый прогон первым) и config (объект из [руководства по анализу](ANALYSIS.md)). После завершения доступны analysis.json, x.svg, y.svg и lag.svg. Используйте имена файлов из ответа задания, например:

```sh
curl -fsS "http://127.0.0.1:8765/jobs/$JOB_ID"
curl -fsS "http://127.0.0.1:8765/jobs/$JOB_ID/artifacts/analysis.json" -o analysis.json
```

## Report builder и авторепорт

В плане укажите два объекта запроса экспорта в массиве exports и настройки анализа в config. Для двух запусков одной панели меняются только границы окна. Ступени задаются относительно начала каждого окна.

```sh
python3 example/reporting/autoreport.py --api http://127.0.0.1:8765 --plan example/reporting/stores.json --out report-001
python3 example/reporting/report_builder.py report-001
```

Первую команду можно запускать из CI или планировщика после завершения прогона. Передавайте отдельный каталог для каждой поставки. Вторая команда повторно собирает локальный index.html из скачанных материалов. Для подключения собственного сборщика отчётов ему достаточно читать JSON и включать SVG из этого каталога.

## Эксплуатация

Сервис по умолчанию слушает 127.0.0.1. Хранилище рассчитано на один процесс в Linux или macOS и использует POSIX-блокировку. Метаданные и результаты сохраняются между запусками. После аварийной остановки незавершённые задания получают статус failed. Готовые задания доступны по прежним id. Автоматической очистки архива нет. Для очистки остановите сервис, сохраните нужные отчёты и удалите каталоги завершённых заданий по их id.

Одновременно выполняются до двух заданий. При суммарно 16 выполняющихся и ожидающих заданиях новый запрос получает 429. Повторите его с паузой. Лимит тела запроса — 64 КиБ, время выполнения задания — 180 с. При 409 проверьте, что оба входных задания имеют тип export и статус succeeded. При failed поле error содержит причину, например отказ Grafana или несовпадение селектора с экспортом. Повторная отправка POST создаёт новое задание.

Для каждого прогона предел сетки — 100 000 отсчётов, предел поиска — 10 000 шагов в каждую сторону и 5 млн сочетаний отсчёта со сдвигом. При превышении лимита сократите окно или диапазон лагов либо выберите более крупный шаг, соответствующий исходным данным.

## Сквозная проверка

Из корня репозитория выполните `CHECK_HTTP_API=1 bash integration/run.sh /tmp/panel2series-http-run1`. Для нового запуска используйте новый каталог. Docker Compose поднимет Grafana, Prometheus 3.15.1 и InfluxDB 1.8.10 и выдаст сервису Viewer-токен. Клиент отчётности обращается по HTTP к сервису. У экспортёра есть сетевой маршрут к Grafana, а источники находятся в отдельной сети.

Проверка запрашивает две панели за одно окно с шагом 60 с. Для Prometheus эталон x равен [2, 7, 4], для InfluxDB — [3, 9, 5]. В каждой панели y = 2 × x. Ошибка третьего запроса B сохраняется в исходном JSON. Проверяются метки, точки, разница средних (+4/3 для x, +8/3 для y), лаг 0 мс по трём парам и ссылки HTML на три читаемых SVG. Эталон с ненулевым лагом описан в [офлайн-примере](ANALYSIS.md). Результат запуска лежит в подкаталоге http. [Готовый HTML с Grafana 11.5.2](example/reporting/verified/index.html).

Сценарий прошёл на Grafana OSS 10.4.19, 11.5.2, 12.0.0 и 13.3.0 для обоих источников. Для повтора всей матрицы выполните `CHECK_HTTP_API=1 bash integration/matrix.sh /tmp/new-http-matrix`. HTTP API обслуживает числовой экспорт панелей. Браузерный экспорт PNG и CSV доступен через существующий CLI.
