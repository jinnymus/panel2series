# Офлайн-анализ двух прогонов

Из корня репозитория запустите команду стандартным Python 3. Входные файлы уже находятся в примере.

```sh
python3 offline_analysis.py example/analysis/run1.json example/analysis/run2.json --config example/analysis/config.json --out example/analysis/report
```

Для своих данных укажите два числовых JSON-экспорта и скопируйте конфигурацию примера. В каждом архиве должны присутствовать обе метрики. Селекторы x и y задают запрос refId, поле field и метки labels. Для осмысленного сравнения проверьте одинаковую семантику запросов, единицы и шаг в обоих прогонах.

step_ms задаёт шаг наблюдений в миллисекундах. Границы ступеней stages отсчитываются от начала окна каждого прогона. Левая граница входит в ступень, правая исключается. Например, [30000,60000] означает точки от 30-й до начала 60-й секунды. Располагайте ступени по времени.

analysis.json содержит значения на сетке, интервалы пропусков, число доступных и ожидаемых наблюдений, минимум, максимум и среднее по каждой ступени. stage_changes показывает изменение среднего относительно предыдущей ступени, run_changes — разницу средних второго и первого прогона на одноимённой ступени. При разном покрытии сравните также число наблюдений. На графиках x.svg и y.svg прогоны совмещены по времени от начала окна, линия прерывается на пропусках.

lag.svg показывает коэффициент Пирсона для сдвигов от −max_lag_steps до +max_lag_steps. Выбирается максимум абсолютного значения корреляции. min_pairs задаёт минимум пар на сдвиг (по умолчанию 3). При нескольких равных максимумах статус ambiguous, при недостатке пар или постоянном сигнале — insufficient. Положительный лаг означает, что y следует за x. Оценка относится ко всему окну. Для каждого сдвига используются только пары с двумя наблюдениями. У трендов, периодических сигналов и больших сдвигов с малым перекрытием возможны ложные пики. Проверяйте форму кривой и число пар. Сам по себе пик не доказывает причинную связь.

## Эталон

Генератор example/analysis/generate.py создаёт два прогона с шагом 1 с. В обоих y(t) = 2 × x(t − 4 с) + 5. Пропущены две точки x и одна точка y. Во втором прогоне x увеличен на 7, y на 14. Исходные окна разнесены на сутки. Для автоматической проверки выполните `python3 -m unittest -v test_analysis`.

Сетка начинается точно в window_ms[0]. Дубликаты и смещённые относительно этой сетки точки вызывают ошибку. Для такого экспорта сначала согласуйте начало окна и шаг. Пропущенная отметка, null и нечисловое значение NaN учитываются как пропуск. Формат v1 содержит один ряд и не хранит field. Для анализа двух разных метрик используйте многорядный экспорт v2. Ступени должны помещаться в оба окна и не пересекаться.
